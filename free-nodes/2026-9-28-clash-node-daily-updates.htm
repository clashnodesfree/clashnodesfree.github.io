局域网流量管家：Quantumult 从入门到精通的实战配置手册

引言：为什么你的局域网需要一位“智能调度员”

在家庭网络设备动辄十数台、办公环境跨层跨楼、科研机构对数据流向高度敏感的今天，传统路由器的“一刀切”式管理早已捉襟见肘。你是否有过这样的经历：客厅的电视盒子正在疯狂上传缓存，导致书房里视频会议卡成PPT；孩子卧室的平板深夜还在刷短视频，而你设定的“家长控制”形同虚设；实验室的传感器数据被后台云同步抢占带宽，关键传输延迟飙升……这些场景的共性在于——局域网内部缺乏基于用户意图的流量治理。而 Quantumult，这款诞生于 iOS/macOS 生态的“网络瑞士军刀”，恰恰能通过其强大的本地规则引擎与代理协议兼容性，将你的局域网从一个“被动共享的管道”升级为“主动调度的智能网络”。

本文不打算复述官方文档，而是基于真实使用场景，手把手带你完成 Quantumult 在局域网中的深度配置，并解析那些容易踩坑的细节。全文约 2500 字，建议收藏后分步操作。

第一章：重新认识 Quantumult——它不只是“代理客户端”

多数人提起 Quantumult，第一反应是“科学上网工具”。这没错，但格局小了。在局域网语境下，Quantumult 更像是一个具备流量整形能力的本地策略网关。它的核心价值在于三点：

  1. 协议多面手：原生支持 HTTP(S)、Shadowsocks、Vmess、Trojan 等主流代理协议，这意味着无论你的上游出口是机场订阅还是自建节点，它都能无缝对接。
  2. 规则引擎的“乐高哲学”：你可以像拼积木一样，将不同设备、不同域名、不同 IP 段指向不同的处理策略——直连、走代理、拒绝访问，甚至自定义响应。
  3. 可视化流量显微镜：实时监控每个连接的去向与消耗，这为局域网排障提供了前所未有的透明度。

正是这三点，让 Quantumult 在局域网中扮演了“软路由大脑”的角色，而无需更换任何硬件。

第二章：部署前的三个关键认知

在动手配置前，请先确认以下三个前提，否则后续操作可能事倍功半：

  • 运行载体：Quantumult 只能在 iOS 或 macOS 设备上运行。因此，你需要有一台长期在线（或可按需唤醒）的 iPhone、iPad 或 Mac 作为“控制节点”。这台设备需与你的目标局域网处于同一 Wi-Fi 或网段内。
  • 网络拓扑：Quantumult 不是网络层 VPN，它工作在应用层（基于系统代理或 TUN 模式）。这意味着，它无法像路由器一样劫持所有设备的 TCP/IP 流量。要让“局域网其他设备”受益，你需要开启 Quantumult 的 “局域网共享（HTTP/HTTPS 代理）” 功能，或者将其所在设备设为网关（后者需要更高级的 TUN 模式及路由表配置，本文重点介绍前者，即代理共享模式）。
  • 上游出口：请提前准备好你的代理服务器信息（订阅链接或手动节点参数）。如果没有任何外部代理，Quantumult 依然可以作为“纯规则过滤工具”使用，实现局域网内的广告拦截、恶意域名屏蔽等，但无法实现跨地域加速。

第三章：手把手——局域网共享配置五步法

第一步：安装与基础激活

App Store 下载 Quantumult（付费应用，但物有所值）。首次打开后，请授予其“本地网络”权限和“VPN 配置”权限（后者用于创建虚拟网卡，实现 TUN 模式）。进入主界面，你会看到“配置文件”“节点”“规则”三个核心菜单。

第二步：导入或创建节点

如果你有订阅链接，点击“节点”页右上角的“+”号，选择“订阅”，粘贴链接并拉取。Quantumult 会自动解析出所有服务器。如果你只有单个节点，选择“手动添加”，按需填写服务器地址、端口、加密方式、密码或 UUID。

局域网特殊提示：如果你的代理服务器本身就位于局域网内（比如你有一台 NAS 跑着 V2Ray），请直接填写其内网 IP，例如 192.168.1.100:8080。这能避免流量绕行公网，极大降低延迟。

第三步：定义“局域网策略组”

这是整个配置的灵魂。点击“配置文件”页，选择“编辑”>“策略组”。建议创建以下三个策略组：

  • PROXY（代理组）：包含你的所有外部节点，用于访问境外网站或特定应用。
  • DIRECT（直连组）：明确指定国内网站、局域网 IP（如 192.168.1.0/24）、组播地址等走直连。
  • BLOCK（拒绝组）：用于屏蔽广告域名、跟踪器或你不想让某设备访问的站点。

策略组的妙处在于，你可以设置“自动测试”或“手动切换”，还能按时间段生效（例如晚 11 点后强制家庭设备进入 BLOCK 组）。

第四步：开启局域网共享（关键步骤）

在 Quantumult 主界面，下拉至“设置”>“代理”>“局域网共享”，开启开关。此时，Quantumult 会监听本机某个端口（默认 8888 或 6152）。记下这个 IP 和端口，例如 192.168.1.50:8888。

注意：为了确保稳定，建议在 macOS 上关闭防火墙对 Quantumult 的拦截，或在 iOS 上允许“本地网络”权限。否则，其他设备将无法连接到这个代理端口。

第五步：为局域网设备分配规则

这是区别于普通代理客户端的神来之笔。回到“配置文件”>“编辑”>“规则”，你需要添加三类规则：

  • 源地址规则（source-geoip 或 source-ip）：指定某台设备的 IP 走哪个策略组。例如：

    • source-ip=192.168.1.100, PROXY （让客厅电视的所有流量都走代理，以便解锁流媒体）
    • source-ip=192.168.1.101, DIRECT （让打印机只走直连，避免代理干扰局域网打印协议）
    • source-ip=192.168.1.102, BLOCK （限制某台设备在特定时段访问外网）

  • 域名规则：即便同一台设备，也可细分。例如：

    • host-suffix=example.com, PROXY
    • host-keyword=ads, BLOCK

  • 目标 IP 规则：确保局域网内部流量（如 NAS 访问）永不绕路。

    • ip-cidr=192.168.1.0/24, DIRECT
    • ip-cidr=10.0.0.0/8, DIRECT

完成以上配置后，保存并启用配置文件。此时，局域网内的任何设备，只要手动将其 Wi-Fi 代理设置为 192.168.1.50:8888，就能被 Quantumult 接管。

第四章：进阶实战——从“能用”到“好用”

场景一：家庭共享网络中的“设备分级”

假设你家有 5 台设备：你的 Mac（工作）、妻子的 iPhone（购物）、孩子的 iPad（学习+娱乐）、客厅电视（流媒体）、智能音箱（IoT）。你可以这样设计：

  • Mac 和 iPhone 走 PROXY，保证境外资料加载速度。
  • iPad 设置策略组“儿童模式”——上午 8 点到下午 6 点仅允许 DIRECT 访问教育类域名，其余时间全 BLOCK。
  • 电视强制 PROXY，且指定仅允许 Netflix、YouTube 域名，其他视频站直连，避免“盒子全家桶”后台偷跑流量。
  • 智能音箱全部 DIRECT，并添加规则禁止其访问未知的云端升级服务器（减少隐私泄露风险）。

场景二：办公室局域网带宽优化

公司网络常被视频会议、云盘同步、软件更新抢占。利用 Quantumult，你可以：

  • 将视频会议软件（Zoom、Teams）的域名强制 DIRECT，并标记为“高优先级”（Quantumult 支持简单的 QoS 标记，但需配合路由器）。
  • 将系统更新服务（如 swcdn.apple.com）指向 BLOCK，仅在午休时段放行。
  • 对设计部的大文件传输走 PROXY 但使用压缩率更高的节点，降低带宽占用。

场景三：实时监控与日志排障

Quantumult 的“流量”页面会列出每个连接的五元组（源 IP、目标 IP、端口、协议、策略结果）。当某设备反应“网速慢”时，你无需登录路由器，直接在 Quantumult 中筛选该设备 IP，即可看到它正在访问哪些域名、走了哪条线路、耗时多少。这比任何网管软件都直观。

第五章：常见问题与避坑指南

  • Q1：其他设备设置了代理后无法上网？
    检查 Quantumult 所在设备的 IP 是否固定（建议在路由器中做 DHCP 静态绑定）。另外，确认 Quantumult 的“局域网共享”端口未被系统防火墙拦截。最后，查看“规则”中是否有 ip-cidr=0.0.0.0/0, DIRECT 这类兜底规则，它可能让代理失效。

  • Q2：为什么部分 App 不遵守系统代理？
    有些应用（如某些游戏、银行 App）强制绕过系统代理。此时你需要开启 Quantumult 的 TUN 模式（需在 iOS 中允许创建 VPN）。TUN 模式会虚拟一张网卡，接管所有 TCP/UDP 流量。但注意，TUN 模式下，你的 Mac/iOS 设备本身会成为网关，其他设备的代理设置反而应指向该设备 IP。

  • Q3：代理延迟高，如何优化？
    在“节点”页，对每个节点开启“健康检查”（URL 测试），并设置策略组为“自动测试-容错”。Quantumult 会自动选择延迟最低的节点。同时，确保局域网内没有其他设备占用大量上行带宽——你可以用 Quantumult 的流量监控揪出元凶。

  • Q4：Quantumult 能替代路由器固件吗？
    不能完全替代。它无法处理 DHCP、NAT、端口转发等三层功能。但对于绝大多数 HTTP/HTTPS 流量治理，它比刷 OpenWrt 更简单、更安全，且不折腾硬件。

点评：这把“网络手术刀”的优雅与锋芒

Quantumult 在局域网中的价值，绝非“给手机挂个代理”那么简单。它提供了一种以策略为中心的网络治理范式——你不需要理解复杂的路由协议，只需像写“if-then”逻辑一样，告诉它“谁在什么时间、什么条件下、可以访问什么”。这种抽象能力，正是现代网络管理的精髓。

它的优雅在于：你完全掌控规则，但又不必陷入底层细节。它的锋芒在于：当你把局域网内所有设备的流量都汇聚到一个小小的 App 上时，你实际上获得了一张动态的、可编程的“网络地图”。每一次规则调整，都像是在地图上重新绘制道路——这比物理上更换一台昂贵的企业路由器，来得更轻巧、更精准。

当然，它也有局限：依赖单点设备（如果那台 iPhone 没电，全网瘫痪）；不支持 UDP 的完整转发（某些游戏语音可能受影响）；规则过多时，调试会变得复杂。但瑕不掩瑜，对于那些追求“精细控制”又不愿深陷命令行泥潭的用户，Quantumult 无疑是当下局域网流量管理中最具性价比的解决方案。

最后提醒一句：工具无罪，规则在人。当你赋予 BLOCK 组权限时，请谨慎——网络的自由与限制，往往只隔着一行规则的距离。希望这篇指南能帮你构建一个既高效又可控的局域网环境。

FAQ

Trojan-go 如何启用 WebSocket 支持？
在配置文件中将 transport 参数设置为 websocket，并指定 path 路径。客户端需同步使用相同路径及主机名。这样可将 Trojan 流量伪装为普通 WebSocket 通信以提升隐蔽性。
Hysteria2 的多路复用功能有哪些优势？
多路复用允许多个请求共享同一 QUIC 连接，减少握手次数和延迟。高并发情况下可以提升吞吐量和稳定性，特别适合短连接频繁请求的应用，如游戏或即时通讯。
Sing-box 的策略组如何实现按域名分流？
Sing-box 支持根据域名规则匹配流量，将不同网站或应用流量分配到指定节点。结合策略组自动切换低延迟节点，可优化访问速度，保证网络稳定性和流畅体验。
Sing-box 的路由规则能否实现分国家代理？
Sing-box 支持 GeoIP 路由规则，通过引入国家数据库可根据 IP 自动判断地理位置。例如可设置 CN 走直连，US/JP 走代理，以此实现分国家策略路由，适合需要访问不同地区内容的用户。
如何优化 Clash 的 DNS 设置？
在 Clash 中使用自定义 DNS 可以加快域名解析速度。建议使用 doh（DNS over HTTPS）或 dot（DNS over TLS）配置方式，既能提升速度，也能保护隐私防止 DNS 泄露。
Surfboard 支持按应用分流流量吗？
